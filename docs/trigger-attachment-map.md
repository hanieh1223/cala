# نقشه اتصال Triggerها در ProcessMaker 3.5.8

کدهای پوشه triggers الگوهای مرجع هستند و قبل از استفاده باید با API دیتابیس و تنظیمات دقیق نصب ProcessMaker مقصد بازبینی شوند.

| فایل | محل اتصال پیشنهادی | توضیح |
|---|---|---|
| 01_validate_and_calculate.php | بعد از Submit فرم درخواست و پیش از Gateway | اعتبارسنجی سمت سرور، محاسبه TOTAL_AMOUNT، تعیین نتیجه |
| 02_persist_request_and_review.php | پس از محاسبه و در هر دو شاخه تأیید/رد | ثبت درخواست و نتیجه بررسی |
| 03_validate_and_persist_payment.php | بعد از Submit فرم پرداخت و قبل از End موفق | اعتبارسنجی پرداخت، ثبت پرداخت، تغییر وضعیت به PAID |

## مواردی که باید پیش از فعال‌سازی اصلاح/تأیید شوند

- روش اتصال DB و نام connection در نصب واقعی.
- پارامترسازی Queryها با API پشتیبانی‌شده نصب؛ استفاده از addslashes به‌تنهایی دفاع کافی در برابر SQL injection نیست.
- تراکنش اتمیک برای درج درخواست و بررسی.
- مدیریت Duplicate Key به‌صورت idempotent؛ قیود یکتا به‌تنهایی تجربه ارسال مجدد را مدیریت نمی‌کنند.
- تولید REQUEST_NUMBER یکتا در سمت سرور و عدم اتکا به مقدار فرم.
- هماهنگی نوع و نام متغیرهای ProcessMaker با قرارداد docs/field-map.md.
- اطمینان از اینکه متغیرهای @@ در Triggerهای ProcessMaker 3.5.8 در context موردنظر قابل دسترسی هستند.
- ثبت پرداخت و به‌روزرسانی درخواست باید در یک تراکنش باشند.
- اگر فرم پرداخت اجازه وضعیت «پرداخت نشده» دارد، نباید Trigger نهایی آن را به End موفق هدایت کند؛ باید مسیر انتظار/اصلاح طراحی شود.

این کدها را بدون انجام موارد بالا روی سامانه عملیاتی اجرا نکنید.
