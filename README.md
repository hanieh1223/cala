# فرایند مدیریت درخواست خرید — ProcessMaker 3.5.8

> وضعیت تحویل: **بسته منبع و مستندات آماده‌سازی شده؛ فایل PMX نهایی هنوز تولید نشده است.** این مخزن در حال حاضر شامل فایل‌های کمکی، مدل BPMN مرجع، SQL، کدهای Trigger و تست‌های منطقی است. هیچ ادعایی درباره Import یا اجرای واقعی در ProcessMaker مطرح نمی‌شود.

## قانون تصمیم‌گیری

همه مبالغ بر حسب تومان و از نوع عدد صحیح هستند:

- `TOTAL_AMOUNT = QUANTITY * UNIT_PRICE`
- حد نصاب: `2,000,000,000`
- تأیید: `TOTAL_AMOUNT <= 2000000000`
- رد خودکار: `TOTAL_AMOUNT > 2000000000`

محاسبه در سمت سرور انجام می‌شود. مبلغ کل ارسالی از مرورگر منبع معتبر نیست.

## ساختار مخزن

- `process/purchase-request-reference.bpmn`: مدل مرجع BPMN 2.0؛ جایگزین PMX نیست.
- `tables/purchase-tables.sql`: ساخت سه جدول عملیاتی و ایندکس‌های یکتا.
- `triggers/`: منطق PHP مرجع برای اعتبارسنجی، محاسبه، بررسی و ثبت داده.
- `docs/`: راهنمای پیاده‌سازی و استقرار.
- `tests/`: تست‌های منطق مبلغ و سناریوهای کسب‌وکار.

## نکته مهم درباره PMX

در ProcessMaker 3.5.8، فایل `.pmx` بسته Export بومی ProcessMaker است و صرفاً تغییر پسوند یک فایل BPMN یا ZIP دلخواه، آن را به PMX معتبر تبدیل نمی‌کند. خروجی بومی شامل اشیای ProcessMaker مانند Variables، Dynaforms، Triggers و تنظیمات فرایند است. PM Tables نیز جداگانه منتقل می‌شوند.

برای تولید PMX واقعی باید فرایند در یک نمونه ProcessMaker 3.5.8 ساخته و از Designer با گزینه Export Process صادر شود. تا زمانی که این مرحله روی نمونه واقعی انجام نشده، فایلی با پسوند PMX در این مخزن قرار داده نمی‌شود تا فایل نمایشی یا غیرقابل Import به‌عنوان خروجی نهایی جا زده نشود.

## راه‌اندازی

1. پایگاه داده و نسخه PHP/ProcessMaker مقصد را پشتیبان‌گیری کنید.
2. فایل `tables/purchase-tables.sql` را در دیتابیس مناسب اجرا کنید؛ پیشوند و دسترسی‌ها را با سیاست نصب خود تطبیق دهید.
3. فرایند را مطابق `docs/process-design.md` در Designer نسخه 3.5.8 ایجاد کنید.
4. متغیرها، فرم‌ها و Triggerها را مطابق مستندات متصل کنید.
5. Triggerها را ابتدا در محیط آزمایشی اجرا و دسترسی SQL را محدود کنید.
6. پس از تکمیل در Designer، از خود ProcessMaker خروجی PMX بگیرید و Import آن را در یک workspace آزمایشی دیگر بررسی کنید.
7. کاربران/گروه‌های تخصیص‌یافته را در محیط مقصد جداگانه تنظیم کنید.

## آزمون

تست مستقل منطق در `tests/test_business_rules.py` قرار دارد. اجرای آن:

```bash
python -m unittest discover -s tests -v
```

این تست‌ها آزمون واحد کد پایتون مرجع هستند و **تست ProcessMaker نیستند**. هیچ نمونه ProcessMaker 3.5.8 در این محیط برای Import، اجرای Case یا آزمون UI در دسترس نبوده است.
